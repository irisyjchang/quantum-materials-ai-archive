## Field rules for new scans

- **Name, date, JC.** Preserve the written labels and carry a shared header down to its rows only when the page structure supports it. Store dates as `YYYY-MM-DD` or `YYYY-MM` at the precision the source supports. If the header lacks a date, check the start and end timestamps and record the evidence for the inferred date. If they disagree or span months with no clear growth date convention, flag it. Preserve a short JC suffix such as `06` as written and leave the full JC blank until confirmed. Older entries may lack a JC number. Sort by date, use confirmed JC numbers to break date ties, and use name alphabetically for ties without JC numbers. Compare confirmed JC order with date order as a check. Keep both raw values if the orders conflict.
- **Composition and stoichiometry.** Capture the raw compound, symbolic formula, written `x`, ratio as written with its component order and basis where known, calculated masses with units, and measured masses separately when present. Distinguish the target formula from the starting charge, which can contain excess flux. Keep blanks, slashes, zero, and overwritten text distinct. Preserve raw cell precision and units. If a writer enters `x = …` in the formula cell or another column, place it in normalized `x` only when its meaning and row are clear. Treat a 5% dopant as `x = 0.05` when the source defines `x` as that site's fraction.
- **Derived x.** For elemental masses, calculate moles with `nᵢ = mᵢ / Mᵢ`. For compound reagents, use the compound molar mass and multiply by the element's formula coefficient. Use the site or substitution model stated by the researcher to compute `x`. For a confirmed binary substitution site this may be `n(dopant) / (n(dopant) + n(host))`, using the moles allocated to that site. Excess host or dopant in the charge can invalidate the use of the bulk masses in this formula. Preserve the inputs, source of molar masses, basis, and calculation separately from the handwritten value. Flag undefined `n` or other symbols and ask what they mean on that sheet. [CIAAW standard atomic weights](https://ciaaw.org/atomic-weights.htm)
- **Furnace cycle.** Capture the full ordered program from text or the time–temperature graph. A ramp changes temperature and has a start, target, and duration or rate where written. A dwell holds temperature for the written duration. For example, transcribe “ramp to 850 in 24 hours, dwell for 4 hours” as two steps, with the ramp start and any unspecified temperature unit left unknown. On a graph, a labeled horizontal segment can establish a dwell and a downward segment can establish cooling. A single temperature with no preceding point or direction needs review. Record `room temperature` if written and preserve each decant event and temperature separately. Two temperatures could be simultaneous zones, successive steps, or separate decants. Use the surrounding labels, graph, and notes to distinguish them.
- **Technique and transport agent.** Look at the main columns and margins for the material, amount, and unit, such as iodine at 10–15 mg. An agent plus explicitly labeled simultaneous zones supports a CVT classification. Two unlabeled temperatures alone leave the interpretation open. A strongly excess charge ratio such as 100:1, a melt–hold–slow-cool program, and a terminal decant together support flux growth. Keep a technique inferred from clues separate from a technique explicitly named on the page. For borderline flux cases, use the pure component's melting point as context and check composition-specific phase information for liquid present at the proposed decant temperature. Flag the classification if the phase state or mixture is unknown. [CVT growth example](https://doi.org/10.1007/s13538-024-01554-3), [Solution growth and decanting study](https://arxiv.org/abs/2503.10374)
- **Layout and optional data.** Record layout as present, absent, or unknown. For a present drawing, save an image cropped from the source with its page and orientation, including zone and door labels where relevant. Use the same crop filename across runs. Capture optional measurements and start/end timestamps when written. Leave Load out of the normalized pilot fields. Keep the original scan and raw extraction.

## Five-model pilot

1. **Select identical inputs.** Start with Run 01 and 3–5 additional representative records. Cover flux, CVT, a drawn layout or graph, a short or missing JC, and ambiguous handwriting across the set if available. Scan paper pages with margins and orientation intact. Give each worksheet, page, section, and populated row a stable locator before extraction. Track duplicate copies across Drive, Dropbox, and Slack against the same source identity when supported by the files. Keep alternate source links in the inventory.
2. **Run independent transcriptions.** Test ChatGPT (the notes specify 6.1 and Run 01 recorded GPT-6.1 Sol at medium reasoning), Claude, Muse, Gemini, and Grok. Record the exact tool, model/version, settings, prompt version, and input pages for each run. Confirm which Muse tool the lab means and which tools are approved for lab data, including any UW Purple route. Use the same page images and instructions in separate sessions. Keep Run 01 as a baseline and rerun ChatGPT with the shared pilot instructions so all five votes use the same contract.
3. **Compare before review.** Save each raw response and generate one [comparison packet](sqlite/README.md) per run. Align rows by worksheet, page, section, and row locator. Compare the normalized value and its status for each field. Keep the evidence from each run available to the reviewer. Green means all five submitted the record and agreed with no review flag. Red means disagreement, a missing response or core field, a derived or inferred value, a partial JC, a missing layout crop, or an unreadable or ambiguous item. A blank JC on a historical record is allowed. If a model cannot run, record the pilot as incomplete and report any smaller comparison with its actual denominator.
4. **Have the lab check the originals.** Lock the comparison first. Have the lab lead or designated researcher open every red source page and a sample of green pages during the pilot. For each flag, show the field, page and row, readings from all models, and a question specific enough to resolve it. Example: “Page 1, Calculated row 2, Compound. The last digit of x is overwritten. Can you confirm the intended value?” Record the reviewer, date, decision, and reason. Green measures model agreement. Human review is a separate status.
5. **Decide whether to expand.** Report records attempted per model, field accuracy against the reviewed scans, red and green counts, shared mistakes on checked green records, and review time. Compare the five-model result with the same records evaluated by the GPT/Claude/Gemini subset proposed for the archive MVP. Resolve the notation questions with the professor and PhD student before accepting automated results. Expand to the remaining scans once the lab has reviewed the pilot.
